# Workflow lab digest (short)

**Full kits:** `UNIVERSAL_DEEP_REASONING.md` · `ADAPTIVE_TASK_EXPANSION.md` · `CHUNKING.md` · `RUNTIME_CONTROL.md` · `FAILURE_MODES.md` · `ANALYSIS_PROMPT_FORMATION.md` · `AI_WORKFLOW_STACK.md` · `PASTEABLES_INDEX.md`

**Intent ≠ full specification.** Short requests are goals; expand to the rigor the task needs — no more.

**Phrase lock:** “please review this project” / “review this” / “full review” / “fine-tooth” → **Mode D** + Adaptive §14 coverage bar + Universal decide-next. **Do not ask which mode.**  
**Also:** “organize the repo” / “extract what is useful” / chat dumps → `EXTRACT_AND_ORGANIZE.md`.

**Automatic 5W1H** (reason always; show on substantial work): Who · What · Why · When · Where · How. Certainty: Known → Inferred → Unknown → Recommended.

**Runtime stanza** (substantial work): one visible line — `Mode · Seat · Multitask · Plan?` — then proceed. Multitask **off** unless independent work has a synthesis owner. **No review fleets.**

**Prefer:** understand → verify → simplify → plan → execute → validate → **stop**. Goal = best justified outcome with least unnecessary complexity — not maximum activity. Say **do nothing** when that is correct.

**Large scope:** semantic chunking → investigate → cross-chunk → **synthesis before conclusions**. Pin: **Chunk for processing, never for understanding.** On long sessions: **FIC** — compact high-signal state after each slice and re-inject (`CHUNKING.md` §5b).

**If the session goes wrong:** name the failure mode (`FAILURE_MODES.md`), stop, re-spec, resume at the right layer — don’t prompt harder on a bad stack.
