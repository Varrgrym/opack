# Chunking (thin pin)

**Status:** active thin kit · 2026-08-08  
**Archive:** `archive/CHUNKING.md` (full essay)  
**Pin:** **Chunk for processing, never for understanding.**

---

## When

Project or task exceeds reliable single-pass reasoning.

## How

1. Split on **semantic** boundaries (module, API, decision, subsystem) — not arbitrary token counts.  
2. Investigate each slice with enough local context.  
3. **Cross-chunk + synthesize** before project-level conclusions.  
4. Long sessions: **FIC** — compact high-signal state after each slice; re-inject before the next.

## Don’t

- Conclude from one slice as if it were the whole.  
- Spawn review fleets instead of synthesizing.  
- Expand scope while chunking “just in case.”
