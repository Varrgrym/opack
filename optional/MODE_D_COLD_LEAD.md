## Posture

- Cold lead: evidence from **this** repo first; no loyalty to prior chat conclusions.  
- Prefer simplification and consolidation over new subsystems.  
- **Do not unlock builds** unless the operator asks.  
- Label: verified · strongly inferred · uncertain.  
- Author ≠ sole reviewer on scary conclusions (hand to Reviewer seat if irreversible recommendations).

---

## Restraint litmus (portable)

Before recommending expansion, ask:

1. Does this belong in **this** repo’s stated purpose?  
2. Can an existing component absorb it?  
3. Is the gap capability, or integration/docs/config?  
4. Would **do nothing / archive / exercise** be higher leverage?

Garden plants: organ/refuse litmus stays on the hub — do not invent Immune here.

---

## Cold-lead pass (order)

1. Purpose & intended behavior (docs + entry points)  
2. Map structure (semantic chunks if large → synthesis)  
3. Trace critical paths; verify claims  
4. Doc ↔ code drift  
5. Gaps / duplication / complexity / coherence  
6. Strengths to preserve · what NOT to touch  
7. Prioritized actions (P0–P3 + do-not) · stop points  
8. Final: Do now / next / later / do not · milestone proof  

Optional: after inspection, Mermaid of **actual** architecture (label intent separately).
